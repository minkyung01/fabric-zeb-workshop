# 10. 마무리

[목차](../README.md) \| 이전: [09. Operations agent](09-operations-agent.md)

공공 인증 데이터와 현장 데이터를 연결해 D단지의 본인증 위험을 찾고, 근거를 확인하고, 담당자 승인으로 보완안을 반영했습니다. 마지막으로 만든 결과를 확인하고 실습 중인 감시·실행을 멈춥니다.

이 장의 미션: “위험 판단에 사용한 근거, 사람이 승인한 보완안, 데이터에 반영된 결과”를 구분해 설명합니다. 결과 대조 → 에이전트 Stop → Spark 세션 중지로 마칩니다. 선택 실습을 생략했거나 에이전트 질의가 미확인이었던 부분은 실행 완료와 구분해 남깁니다.

시작 전: 09장의 승인·결과 확인·Operations agent Stop을 마쳤는지 확인합니다. 결과를 확인하려고 승인 Notebook이나 02장을 다시 실행하지 않습니다.

## 1. 만든 것 확인하기

| 장 | 만든 것 | 확인할 결과 |
|---|---|---|
| 02–03 | Bronze 21개 | 공공 인증 4종(ZEB 9,760행 등)을 Notebook으로 내려받아 원천 그대로 저장하고, Contoso 내부 16개 테이블을 만들었습니다. |
| 04 | Silver 21개 | 시도·용도·등급 표기를 통일하고, 같은 건물을 묶고(25,362개), 발주 이벤트를 반영했습니다. |
| 05 | Gold 22개, ops 3개 | 업무 데이터(Gold)와 판정 결과(ops)를 나눠 저장했고, D단지가 예상 5등급으로 위험임을 확인했습니다. |
| 06 | Ontology `ont_zeb` | 시스템별 코드·인증 설계안·등급 판정·일정 연쇄 규칙을 담았습니다. |
| 07 | Data agent `da_zeb`, Ontology Agent Plan 질의, `05_answers` | Data agent를 구성하고 Plan에서 질문 8개를 정답 Notebook과 비교해 정답·오답·미확인을 구분했습니다. |
| 08 | (선택) `sm_zeb`, `rpt_zeb` | 진행한 경우 현장 컨트롤 타워 보고서가 있습니다. 건너뛰었다면 없어도 됩니다. |
| 09 | `eh_zeb`, `oa_zeb`, `06_risk_event`, `nb_apply_decision` | 추천 보완안 `OPT-D2`(2억 3천만 원, 41.4% → 4등급)를 Teams로 제안받아 승인했고, 조치 기록 → 설계안 V4 → 4등급·정상 → 이벤트 `resolved`까지 반영했습니다. |

같은 Gold 데이터의 근거를 정답 Notebook·원본 SQL·에이전트에서 비교했고, 결정은 담당자가 Teams에서 했습니다. 추천은 Notebook 계산으로 정하고, AI의 설명은 그 계산과 대조했습니다. 보고서는 선택 08장을 진행한 경우에만 확인합니다.

## 2. 감시와 실행이 멈췄는지 확인

1.  본인 작업 영역에서 `oa_zeb`를 엽니다. 09장 12단계에서 멈췄다면 도구 모음에 Start가 보입니다. Stop이 보이면 아직 감시 중이므로 Stop을 누릅니다.
2.  열려 있는 Notebook에 활성 Spark 세션이 남아 있으면 Stop session을 누릅니다.

확인할 결과: `oa_zeb`에 Start가 보이고 활성 Spark 세션이 없습니다. Operations agent Stop과 Fabric 용량 일시 중지는 다릅니다. 유료 용량의 비용 관리는 관리자에게 확인합니다.

## 마무리 완료 기준

실습 결과와 승인 근거·반영 결과를 확인했고, 본인의 감시·실행을 중지했으면 완료입니다.
